# 19 - 系統開發邊界（不可衝突條款）

## 1. 目的

建立「系統開發邊界」，確保所有設計與實作不偏離核心方向。

## 2. 不可違反的核心邊界

1. 不可回到傳統敵我血量/格擋/意圖回合戰鬥為主循環。
2. 不可引入 RPG 屬性點（STR/INT/AGI）作為主要強度來源。
3. 不可把學習流程做成考試式中斷（跳窗測驗主導流程）。
4. 不可讓答錯破壞牌型成立條件（答錯只能降收益，不斷流程）。
5. 不可讓契約獎勵壓過主循環（LP 上限 45% 必須維持）。
6. 不可在未更新 SoT 文件時私改平衡數值。

## 3. 衝突判定規則

若提案符合以下任一條件，判定為衝突：
- 與 `docs/01-game-design-core.md` 的玩法規則相反
- 與 `docs/02-meta-progression.md` 的進程規則相反
- 與 `docs/15-balance-source-of-truth.md` 的數值邏輯矛盾
- 與 `docs/03`/`docs/04` 的架構與資料契約不相容

## 4. 衝突處理流程

1. 提案標記：`Design Conflict`
2. 記錄：`docs/SESSION_NOTES.md`
3. 暫停實作：不得進分支程式開發
4. 需改核心設計時：先出 ADR，再更新核心文件，再排程開發

## 5. 允許變更範圍（在不衝突前提）

1. 牌池內容擴充（新增詞彙、卡池密度）
2. 非破壞性數值微調（需同步 SoT）
3. UI 呈現與流程優化（不改核心規則）
4. 測試與可觀測性增強

## 6. 最終原則

- 任何「看起來更好玩」但違反核心設計邊界的改動，一律不採用。
- 核心設計一致性優先於局部創意。
